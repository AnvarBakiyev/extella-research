# Опыт 22. Ширина применения обработчика

14 октября 2026. Повод — разговор с Тимой о статье про CSPL: обработчик своего языка не только исполняет программу, но и проверяет её правилами, без модели; ошибка возвращается модели, она правит строку. Тезис Тимы: «чем лучше продуман язык, тем слабее может быть модель»; «глубина даёт точность, ширина — скорость и экономию токенов».

Вопрос опыта: в каких областях это работает и даёт ли это что-то сверх обычной программы с теми же проверками.

## Протокол, одинаковый для каждой области

Для области делается маленький язык и обработчик: разбор, правила проверки, результат. Набор задач с независимым оценщиком: оценщик знает правильный ответ задачи и проверяет его отдельно от обработчика.

Три способа решить одну задачу одной моделью:

| Способ | Что пишет модель | Проверки | Повторы |
|---|---|---|---|
| A. Один выстрел | программу на Python | нет | 1 |
| B. Python с проверками | программу на Python | те же правила, библиотекой; ошибки возвращаются модели | до 3 |
| C. Свой язык | программу на языке области | те же правила внутри обработчика на устройстве, через Extella | до 3 |

B — честный соперник: это то, что разработчик делает без Extella, через хуки или тест после каждого шага. Отличие C от B — правила стоят в исполнителе, их нельзя пропустить, и модель пишет короче.

Меряем: доля задач, решённых верно по оценщику; число обращений к модели; токены; длина того, что пишет модель; время.

Модель: платформенная Qwen (агент `<agent-large-model>`, без инструментов, только текст программы). Если найдётся меньшая модель на платформе — повтор на ней.

## Области

1. **Детали и сборка** (аналог 3D-примера Тимы, плоский): пластины, отверстия, крепёж, сопряжение. Правила: стенка от края, совпадение отверстий, зазоры, запас прочности по простой формуле.
2. **Вопросы к данным**: маленький язык запросов к таблице; правила: только известные столбцы, типы, только чтение.
3. **Графики смен**: правила труда: длительность смены, отдых между сменами, часы в неделю, покрытие.
4. **Безопасный код**: подмножество Python; правила: запрещённые вызовы, тесты задачи проходят до сохранения.

Отдельно — **ширина в смысле Тимы**: один обработчик, 40 программ. Замена правила одним действием; сломанная версия обработчика и её охват; «обработчик для обработчика» — проверка новой версии на всех программах до замены.

## Предсказания, записанные до запуска

- C и B решат примерно одинаково: правила те же, отличается только место. A — хуже там, где правил много (детали, смены).
- C потребует меньше токенов на ответ модели, потому что программа короче. Насколько — главный вопрос.
- C медленнее B по времени: каждый прогон через платформу 10–15 с против долей секунды.
- На вопросах к данным разница между способами будет малой: сильная модель хорошо пишет такой код и без проверок.
- В «ширине» замена правила дойдёт до всех 40 программ; сломанная версия сломает все 40; проверка до замены это поймает.

## Что не утверждаем заранее

Опыт одной модели и одного набора задач на область. Обработчики пишу я; сколько стоит их написать — тоже часть результата.

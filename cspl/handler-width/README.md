## Модели и настройки

- Большая модель: `qwen3.7-max-2026-06-08`, маленькая: `qwen-flash`. Обе — платформенные модели Extella, вызываются через агентов без инструментов (`<agent-large-model>`, `<agent-small-model>`), temperature 0.2, `store: false`, каждый вызов без памяти о прошлых.
- Попыток: A — 1; B и C — до 3.
- Устройство для способа C — MacBook владельца; обработчики регистрировались на нём перед прогоном.
- Токены — поле `usage.total_tokens` ответа агента, сумма по всем обращениям к модели в задаче (вход + выход, включая рассуждения модели). Подготовка обработчиков (их писал Claude, 34–51 строка на область) в токены и время не входит.
- Время — сумма времени модели и, для C, запусков на устройстве через платформу.

## Что исправлено после некорректного прогона

В первом прогоне смен (`e3_result_INVALID_no_checks.json`) обработчик искал условия задачи в `extra["spec"]`, а платформа передала их внутри `extra["kwargs"]`. Проверка правил не выполнялась, и способ C прошёл без проверок. Исправлено чтение параметров в обработчиках смен и кода (`e3_shifts.py`, `e4_code.py`), правильность проверена отдельными пробами; затем перезапущены: смены на обеих моделях, код на большой. Детали ошибку не задела — там параметры читались правильно с самого начала. Смены на маленькой модели прогнаны трижды (`_f`, `_f2`, `_f3`).

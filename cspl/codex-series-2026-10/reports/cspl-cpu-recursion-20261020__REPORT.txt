CSPL → C И РЕКУРСИЯ ПО СОСТАВУ ИЗДЕЛИЯ
20 октября 2026. Итог завершённой серии.

Оба сценария работают через настоящий CSPL в Extella и через Python
с той же библиотекой. Финальные 48 выполнений отдельных сценариев на двух
исполнителях совпали с заранее сохранёнными правильными ответами.
Подтверждена возможность использовать CSPL для этих задач. Вычисления,
ускорение от C и повторное использование узлов обеспечивает общая библиотека.

1. ДОШЛИ ДО НАСТОЯЩЕГО МАШИННОГО КОДА

Цепочка: JSON с тарифом → зарегистрированный обработчик CSPL → генератор C
→ установленный компилятор → библиотека и отдельная исполняемая программа.
Вторая сторона сравнения: тот же JSON → готовый Python-диспетчер → тот же
генератор, компилятор и библиотека.

Исполнители:
  Mac ARM64: Apple Clang 16, Extella Listener, Python 3.12.13.
  Linux x86-64: GCC 13.3, Extella Listener, Python 3.12.3.

Четыре тарифа проверены на каждом исполнителе обоими способами.
Созданы и запущены реальные Mach-O и ELF файлы. Отдельные программы дали
те же контрольные суммы, что вызов библиотеки. На двух архитектурах исходный
C совпадает; машинные файлы различаются, как и должны.
Повторный Python-вызов использовал уже скомпилированные файлы без изменений.

Локальная численная проверка: шесть тарифов по 100 000 входных сумм,
все 600 000 ответов совпали с независимым Decimal ROUND_HALF_UP.
Дополнительно проверены отдельные программы, некорректные входы,
границы арифметики и запуски с проверкой ошибок памяти/неопределённого
поведения. После исправления генератора 600 000 сравнений повторены.
Это повторная проверка того же корпуса, а не ещё 600 000 уникальных примеров.

Применение: комиссия платёжного сервиса, тариф перевозки, расчёт начислений.
Оператор меняет маленький документ с порогами и ставками, обработчик создаёт
быстрый код, затем его можно многократно применять к большим пакетам данных.
В этой серии реально реализована комиссия с порогами, округлением,
фиксированной частью, минимумом и потолком; остальные задачи — применения
этого подхода, а не отдельные проведённые тесты.

Это работа машинной программы в обычном процессе ОС. Прямое управление
оборудованием, драйверы, микроконтроллеры и произвольная трансляция любого
CSPL в C здесь не проверялись. Обработчик C — написанный нами компонент.

2. ЧТО ПОКАЗАЛО ВРЕМЯ

Локально на Mac, первоначальная версия генератора, пакет 100 000 значений:
  Python с обычным целочисленным циклом: приблизительно 49–65 мс.
  Python с той же скомпилированной C-библиотекой: 18–20 мс с проверкой
    аргументов и преобразованием массивов внутри execute.
  Сам вызов уже подготовленной C-библиотеки: приблизительно 0,038–0,107 мс.

Первый вызов дополнительно требует компиляции. Шесть локальных сборок
заняли суммарно около 1,24 с; в это время входят библиотека, ассемблерный
листинг и отдельная программа. Для одного простого вычисления такая
подготовка может быть дороже самого расчёта.

Эти числа объясняют пользу массовых повторных расчётов и цену передачи
данных. Они не являются сравнением скорости CSPL и Python. У Python
с готовой библиотекой уже есть доступ к тому же быстрому машинному коду.
Замер execute не включает все операции run_case, контрольные суммы,
сериализацию JSON и доставку через Extella. Удалённые времена сохранены
как наблюдения, но не сравниваются: первоначальный CSPL-вызов собирал
код, последующий Python-вызов использовал готовые файлы.

Корпус синтетический; крупные суммы часто попадают в старшие тарифы.
Одноэлементная серия использует нулевую сумму. Небольшие различия времени
при фиксированном порядке и семи повторах не обобщаются.
Первоначальные тайминги не переименованы в измерения исправленной версии.

3. РЕКУРСИВНЫЙ СОСТАВ ИЗДЕЛИЯ РАСЧИТЫВАЕТСЯ ПРАВИЛЬНО

Программа узнаёт дочерние детали при запросе очередного узла. Состав
не требуется предварительно перечислять в порядке вычисления. Готовый
результат общей детали используется повторно с правильным количеством.

Простой проверенный пример: заказ трёх стульев.
  На стул: сборка 40 + четыре ножки по 25 + сиденье 200 + спинка 100
    + шестнадцать винтов по 2 = 472 условные минимальные денежные единицы.
  На заказ: 1 416.
  К закупке: 12 ножек, 3 сиденья, 3 спинки, 48 винтов.
  Запрошены только шесть разных узлов состава.

Другие проверенные ситуации:
  Общий подузел в двух ветвях: 42 болта и стоимость 269.
  Повторяющиеся ссылки с разными количествами: 27 болтов, 20 шайб,
    стоимость 128.
  Цепочка 1 200 уровней: успешно на обоих исполнителях, обоими способами.
  Цепочка 1 800 уровней: успешно в локальной проверке.
  Цикл a→b→a и ссылка узла на самого себя: остановка с указанием цикла.
  Отсутствующий узел, неправильное количество и проверенные пределы
    работы: ожидаемая диагностическая ошибка.

Локально: 100 сценариев, из них 87 корректных составов и 13 ожидаемых отказов.
91 проверка независимым алгоритмом; 19 сверок с заранее заданными ответами.
Пять специально внесённых неправильных вариантов обнаружены проверками.
Второй независимый аудит дополнительно проверил все 64 варианта небольшого
графа с направленными вперёд рёбрами, включая повторные ссылки.

Наглядный эффект повторного использования: в графе из 29 узлов и 56 рёбер
потребовалось 29 чтений. Наивное раскрытие всех повторений потребовало бы
536 870 911 вызовов. Последнее число рассчитано по точной формуле;
полмиллиарда вызовов не запускались. Количество конечной детали при этом
268 435 456 — экономить вычисления нельзя за счёт потери количества.

Применение: мебельная фабрика, сборка оборудования, смета строительства,
расчёт потребности производства в материалах. Один и тот же крепёж или
узел встречается в разных изделиях; его описание запрашивается один раз,
но в заказе учитываются все вхождения.

Проверенный поставщик данных — память с доступом через get, а не настоящая
ERP или сеть. Число чтений нельзя выдавать за замер сетевого трафика.
Обход работает через явный стек в общей библиотеке. Это рекурсивная
структура задачи; на каждом уровне не создаётся отдельный вызов CSPL,
не вызывается модель и не возникает бесконечная цепочка обработчиков.
CSPL здесь запускает такой расчёт. Бесконечный цикл состава — ошибка,
которую программа обнаруживает.

4. ЧТО ИМЕННО СРАВНИЛИ

Для каждой стороны совпадают:
  байты исходного JSON, версия библиотеки и ожидаемый ответ;
  арифметика, компилятор и машинная библиотека;
  алгоритм обхода, кэш готовых узлов и логические ограничения.

Настоящий маршрут CSPL подтверждён журналом Extella:
  CSPL value: cspl_cpu_bom_20261020_a6f2_bom
  CSPL value: cspl_cpu_bom_20261020_a6f2_v2_cpu
Python-контроль запускается через fython и готовый реестр программ.
Оба маршрута передают исходный JSON общей библиотеке; второму не пришлось
заново писать компилятор или алгоритм расчёта состава.

Финальная матрица:
  C: 4 программы × 2 способа запуска × 2 исполнителя = 16.
  Состав изделия: 8 сценариев × 2 способа × 2 исполнителя = 32.
  Все 48 результатов совпали, включая ожидаемые диагностические ошибки.
  158 автоматических проверок результатов, целостности, заголовков
  машинных файлов, кэша и выбранного обработчика прошли.

Практическая роль CSPL в этих опытах — связать описание программы
с нужным обработчиком в Extella. Возможность использовать C и вычислять
сложный состав подтверждена. Преимущество самого CSPL в скорости,
токенах или безопасности из этих результатов не следует:
Python с готовым диспетчером получил тот же результат теми же средствами.

5. ОБНАРУЖЕННЫЕ ОШИБКИ И ГРАНИЦЫ

Первоначальный генератор создавал проверку unsigned fee < 0.
Clang принимал её, GCC со строгими предупреждениями отклонил компиляцию.
Ошибка воспроизвелась и через CSPL, и через Python на Linux.
Исходные неуспешные результаты сохранены. Исправление убирает только
бессмысленную проверку при minimum=0. Положительные минимумы дают тот же
C; исходные JSON и ожидаемые ответы не менялись. Новая версия установлена
в отдельное пространство имён и успешно прошла обе стороны на обеих ОС.

Независимая проверка обнаружила отдельный дефект обработки плохого состава:
искусственно вложенный примерно в 600 списков неправильный узел вызывает
RecursionError внутри deepcopy до валидации. Основной замороженный движок
состава сохранён; дефект и воспроизводимый пример явно записаны.
Для сервиса, принимающего чужие документы, необходимо исправить чтение
и валидацию узла, а затем отдельно проверять ограничения памяти и времени.
Существующие лимиты обхода не являются полной песочницей.

Лимит глубины ограничивает активный стек обхода. Результат из кэша может
лежать на более длинном пути графа. Это соответствует протоколу и не
равнозначно ограничению длины любого пути. Кэш словарей конечных деталей
также расходует память у многих предков.

6. РАСХОДЫ, СОХРАНЁННЫЕ МАТЕРИАЛЫ, ПОВТОРЕНИЕ

Платных вызовов Anthropic/OpenRouter/других моделей: 0; стоимость этих API: $0.
Ключи и буфер обмена не использовались. Работа Codex расходует отдельный
лимит приложения; она не является бесплатной по числу его токенов.

Extella: 8 сохранений Expert, 18 запусков.
  2 проверки компиляторов;
  4 установки (две версии на двух исполнителях);
  8 первоначальных запусков сравнения, включая два сбоя GCC;
  4 повторных запуска исправленного C-сценария.
Сохранены приватные лабораторные Expert и обработчики с префиксами
cspl_cpu_bom_20261020_a6f2 и cspl_cpu_bom_20261020_a6f2_v2.
Вторая установка также содержит обработчик BOM для той же структуры
пакета; второй BOM Expert не сохранялся и его запуски не заявляются.
Системные службы и пакеты не устанавливались.

Основные материалы в этой папке:
  PROTOCOL.txt — исходный план и правила сравнения.
  REMOTE_RESULTS.json — итог автоматической проверки настоящих запусков.
  remote/, remote_v2/ — исходные ответы Extella, программа установки,
    общий JSON, ожидаемые результаты и контрольные суммы файлов.
  cpu/REPORT.txt, cpu/RESULTS.json — локальная арифметика и тайминги.
  cpu/ARTIFACT_PROOF.json, cpu/artifacts/ — C, ассемблер, машинные файлы.
  cpu/AMENDMENT.txt, cpu/engine_v2.py, cpu/V2_RESULTS.json — исправление GCC.
  bom/REPORT.txt, bom/RESULTS.json — состав изделия и независимые проверки.
  REVIEW.txt, audit_checks.py, audit_results.json — независимый аудит,
    включая воспроизводимый недостаток обработки неправильного ввода.

Проверить сохранённые удалённые доказательства без запросов к Extella:
  python3 verify_remote.py
Повторить малый независимый аудит без API и компиляции:
  python3 -B audit_checks.py
Полные локальные серии описаны в отчётах cpu и bom; для новых измерений
нужны отдельные каталоги результатов/сборки, чтобы сохранить первую серию.

Следующий содержательный эксперимент:
реальные изменения состава между чтениями из внешнего хранилища —
фиксированная версия заказа, повторный запуск после сбоя, запрет смешивать
старые и новые детали. Сравнение вновь должно дать Python тот же диспетчер.
Отдельная проверка CSPL на CSPL должна делать узлы самостоятельными
программами с собственными обработчиками. Здесь этого свойства нет,
и результаты глубокого графа его не подменяют.

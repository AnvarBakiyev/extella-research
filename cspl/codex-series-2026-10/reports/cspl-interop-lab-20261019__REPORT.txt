CSPL и Python: новый язык, независимые реализации, закреплённые версии
19 октября 2026

Новый язык и его следующую версию удалось подключить без изменения общего
исполнителя. CSPL и Python с заранее готовым диспетчером потребовали одинаково
ноль изменений этого исполнителя. Прежние программы сохранили поведение.
Дополнительное преимущество CSPL по трудоёмкости подключения здесь не выявлено.

Основной набор:45 заранее подготовленных случаев,30 удалённых запусков,
444 исполнения отдельных программ.252 корректных вычисления и192 ожидаемых
отказа совпали с независимыми эталонами.35 сравнений механизмов, реализаций
и ОС не нашли расхождений на этом наборе.406 проверок свидетельств прошли.

Дополнительный тест за пределами исходных45 случаев выявил настоящий дефект
нашего Python-интерпретатора.400-значное целое число вызвало OverflowError;
JavaScript-интерпретатор корректно вернул отказ integer. У Python-обработчика
ошибка одинаково проявилась и через CSPL, и через обычный диспетчер. Таким
образом, соответствие разных реализаций общей спецификации не возникает
автоматически из выбора обработчика в метаданных. Основной набор не доказывает
полную совместимость на всём допустимом пространстве входов.

Что реально исполнялось

На Mac arm64 были Python3.12.13 и Node26.5.0; на Linux x86_64 — Python3.12.3.
На Linux Node не найден в PATH и трёх обычных местах. Новую среду не устанавливали.
Поэтому Mac проверил независимые Python/JavaScript реализации, Linux — перенос
Python-реализации. Два отдельных Linux-запуска JS дали runtime_unavailable,
по одному через каждый механизм. Исполнение JavaScript на Linux не доказано.

Языки:
  affine1: точное целое x*scale+offset, включая результат1000000000000000001.
  tier1: ставка выбирается по порогу и применяется ко всей сумме.
  tier2: прогрессивная ставка; разные части суммы используют разные ставки.
  В tier1 и tier2 округление задаётся явно: неотрицательное round-half-up.
  Например, amount125,threshold100,low_bp1000,high_bp2000 дают25 в tier1 и15
  в tier2. Неверная схема версии отклоняется, а не меняет смысл молча.

JavaScript написан отдельным агентом по SPEC.txt без чтения Python-реализации;
использует BigInt. Python использует целые числа. Эталоны сформированы отдельно:
для пороговых расчётов через Fraction и деление с остатком. Нет транспиляции
одной реализации в другую. У каждой версии свой самостоятельный файл.

Сначала установлены только affine1-файлы. Затем реально доставлены tier1,
после них tier2; будущие реализации отсутствовали в первоначальном runtime.
После добавлений заново выполнены и tier1, и affine1 во всех основных сочетаниях.

CSPL-путь: JSON Expert + cspl=имя установленного нативного обработчика → общий
runner → самостоятельный Python или Node процесс с выбранной реализацией.
Python-контроль: один заранее установленный generic Expert + параметры binding
и source → тот же runner, реестр, процесс и точно тот же JSON.
В обоих случаях транспорт обеспечивает Extella. Диспетчер Python не переписан
для каждого языка. CSPL-обработчики являются штатными fython-контейнерами;
переход к Node организован нашим одинаковым адаптером, не встроенной гарантией
автоматического запуска/доставки произвольной среды исполнения.

Что потребовалось при расширении

Для нового языка/версии доставлялись две реализации — Python и JavaScript —
и добавлялись две привязки на каждом узле. Прежние реализации и runner сохраняли
точные хеши. Для CSPL создавались именованные нативные контейнеры-обработчики;
готовый Python dispatcher использовал новые записи общего реестра. Шаблон
обёрток не менялся при добавлении языков. Общий установщик готовил обе ветки.

Изменений общего runner:0. Изменений Python generic Expert после регистрации:0.
Хеш нативного executor.so на каждом устройстве тоже остался прежним.
На каждом узле в конце6 новых нативных обработчиков и6 записей общего реестра.
Нельзя считать эти6 контейнеров преимуществом или проигрышем по общей стоимости:
изолированные развёртывания и полный сетевой трафик здесь не измерялись.

Python generic entrypoint занимает467байт локального исходника, runner2408байт.
API при первоначальном сохранении generic убрал одну завершающую новую строку;
между первым и последним чтением сохранённый исходник побайтно одинаковый.
JSON-документы:affine1 —944байта, tier1/tier2 —по1677байт. У обоих механизмов
документы идентичны. Эти размеры не показывают экономию модельных токенов.

Два обнаруженных ограничения, сохранённые без маскировки

1. Первоначальный установщик на обоих узлах успел записать файлы/реестр,
   затем упал на служебном вычислении хеша: executor.__file__ указывал на
   отсутствующий executor.py, хотя установлен executor.so. Повторной установки
   не было. Отдельная read-only инвентаризация подтвердила созданное состояние.
   Исправлен только путь финального аудита в последующих установщиках.
   Оба отказа и исходный код сохранены. Успешный общий вердикт относится к
   восстановленной проверке состояния и исполнению, а не к этим двум ACK.
   Начальный empty-before и plaintext-хеши нативных обёрток тогда не вернулись;
   наблюдаемые хеши их контейнеров начинаются с восстановительной инвентаризации.

2. После основной серии просмотр валидатора выявил потенциальное переполнение
   при math.isfinite на очень большом Python int. Локальная проверка и четыре
   новых запуска на Mac подтвердили его: оба маршрута с Python-реализацией
   вернули implementation_exit, оба с JS — корректный integer-отказ.
   Это дефект нашего обработчика. Ограничение языка само по себе не гарантирует
   корректности его реализации. CSPL здесь не перехватил и не исправил смысл
   ошибки. Общий subprocess-адаптер ограничил её отдельным процессом.
   Исправленный кандидат вынесен в fixes, исходные испытанные файлы сохранены.
   Кандидат проверяется локально; в Extella эта исправленная версия не установлена.

Где сохраняется практическая ценность CSPL

Подтверждено удобное соглашение: артефакт содержит текст и стандартное поле
выбора обработчика. Это позволяет общему клиенту Extella работать с разными
языками и именованными версиями. Применения — каталоги политик, преобразования
данных, одинаковые бизнес-правила в разных средах. При наличии готового Python
dispatcher те же свойства воспроизводятся без изменения его исходника.

Дополнительная ценность может возникнуть на границе независимых продуктов:
сторонний клиент уже понимает формат CSPL и не требует нового интеграционного
API. Этот опыт проверял независимые интерпретаторы, но не независимых сторонних
производителей/клиентов, поэтому экономию интеграции между ними не измерял.

Для безопасности потребуется отдельно доказать право выбора обработчика,
проверку разрешённых возможностей и качество самого интерпретатора. Нынешний
пример с большим числом показывает, почему одного названия ограниченного языка
недостаточно. Хеши, реестр и лимит дочернего процесса здесь принадлежат общему
прикладному коду и одинаково доступны Python.

Расходы и воспроизведение

48 сохранённых ответов run_expert, включая подготовку, два восстановительных
аудита, основные/дополнительные пробы и итоговую инвентаризацию. Платных тестовых
запросов к моделям:0; OpenRouter не использовался. Исследование Codex/субагента
использует лимит Codex. Никакой вывод о сравнении расхода LLM-токенов не делается.

Работа велась только с новым namespace cspl_interop_20261019_e7b3_. Рабочие
Listener и прежние лаборатории не менялись. Тестовые дочерние процессы завершены;
12 private Experts и собственные файлы/контейнеры оставлены для воспроизведения.
Платформенные файлы только читались для хеша. Никаких ключей в артефактах нет.

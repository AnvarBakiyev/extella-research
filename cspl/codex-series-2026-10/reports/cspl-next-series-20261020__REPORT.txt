1. Содержательность задачи и локальная проверка

Компания ограничивает скидку, маржу, список сегментов и договоры; филиал задаёт
дополнительные пределы и исключения; политика определяет пороги, надбавки и акции.
Результат: скидка в минимальных денежных единицах, согласование, маржа,
выбранная акция, объяснение, версия; опционально сумма после скидки.
Влияние каждого уровня проверено отдельными абляциями.

Исходное состояние + 12 изменений:
пороги и их границы, пересекающиеся акции, исключения, новый сегмент,
общий предел, ограничения филиала, дополнительный результат, schema2,
half-up -> half-even, намеренно дефектный обработчик, откат.
32 программы, 200 входов на программу. 12 корректных состояний и одно
намеренно дефектное; это не 76 800 независимых бизнес-задач.

На каждом из трёх ЛОКАЛЬНЫХ маршрутов:
- 76 800/76 800 результатов корректных состояний совпали с отдельным Decimal oracle;
- дефектный обработчик дал 1 373/6 400 ошибочных бизнес-результатов;
- откат полностью восстановил ответы последнего корректного состояния.

Маршруты: прямой вызов библиотеки, прикладной metadata resolver с callable
границами, готовый Python-диспетчер. Второй маршрут здесь не является Disnet.
Оба реестровых маршрута получили одинаковые {name,cspl,code}, одну библиотеку
и общий алгоритм разрешения зависимостей.
После 57 исходных записей понадобилось 85 правок записей, по 202 компиляции
каждому диспетчеру; откат потребовал 0 новых компиляций, новых адаптеров 0.
Это свойства общего реестра/кеша; их нельзя приписать нативному CSPL.

Исходники, oracle, frozen protocol, таблица изменений:
lifecycle/REPORT.txt, lifecycle/FROZEN_SHA256.json,
lifecycle/results/RESULTS.json, lifecycle/results/remote_cases.json.
Независимый review добавил 6 000 сравнений с Decimal oracle без расхождений.

2. Проверка настоящего CSPL в Extella

На своих Mac и Linux установлены одинаковые библиотека, ready Python registry
и три тестовых обработчика: v1, v2, faulty. SHA библиотеки совпадает:
781872434bc5cd150f0f2b13936e645b79a0d296de902c420c53cbda6dd5cb23.
CSPL Expert содержит JSON и metadata cspl с именем зарегистрированного
обработчика. Python Expert вызывает готовый реестр с тем же JSON и библиотекой.
Модельный код не используется для установки или выполнения.

Шесть выбранных snapshots x 2 маршрута x 2 исполнителя = 24 основных run_expert.
Каждый запуск обрабатывает 18 заказов: 432 исполнения случаев.
- 360 исполнений корректных версий: совпали с эталоном;
- 72 исполнения с намеренным дефектом: 44 расхождения с правильным эталоном
  (те же 11 ошибок на 18 входах в каждом из четырёх сочетаний);
- все 12 пар CSPL/Python совпали полностью, включая результаты дефектной версии;
- все 12 пар Mac/Linux совпали;
- 4 проверки возвращения к корректной версии восстановили ответы.

Важная граница: remote snapshots сохранены как отдельные Experts/записи.
Этот этап проверяет выполнение версий и равенство результатов, не новое
испытание распределённого обновления на месте, сбоя доставки или транзакции.
Последовательные изменения и инвалидация кеша проверены в локальном реестре.
Нативной глубокой цепочки из трёх контейнеров в этом новом remote этапе нет:
три бизнес-уровня обрабатывает общая библиотека. Глубокие контейнерные цепочки
были предметом прежних отдельных лабораторий.
Время run_expert включает платформу/транспорт и не является чистым benchmark.

Всего: 8 save_expert, 2 установочных + 24 основных run_expert = 26 запусков.
Созданы 8 приватных Experts с префиксом cspl_b2b_20261020_4c9d,
три новых контейнера обработчиков на каждом своём исполнителе и каталог
cspl_b2b_lab_20261020_4c9d в системной временной директории каждого узла.
Старые лаборатории, общие обработчики и рабочие бизнес-программы не изменены.
Артефакты сохранены для воспроизводимости.
Сырые ответы и проверка: remote/*, verify_remote.py.

3. Модельное сравнение создания изменений и ремонта

Провайдер: официальный https://api.anthropic.com.
Доступность модели проверена через /v1/models, без генерации текста.
Ответы API подтверждают model=claude-haiku-5-5, standard service tier,
global inference, thinking_tokens=0, cache tokens=0.
Двенадцать первичных запросов: два изменения, две миграции схемы,
два исправления конфликтующих зависимых правил, по запросу на формат.
Один короткий общий system prompt, одинаковые требования и начальный JSON.
Форматные инструкции отличаются; их длина в символах почти равна, но
токеновое равенство не заявляется. Порядок форматов чередуется между задачами.
Инструменты и thinking выключены, max_tokens=1200, sampling overrides не заданы.
Каждая исходная задача начинается с нового диалога.
Python получает готовую compile_policy(package,handler_version=...).
Модель не пишет алгоритм расчёта. Ожидаемые ответы и скрытые входы не передаются.

Результаты                    CSPL/JSON       Python factory
Первично принятые программы    6/6             4/6
Первичные input tokens        7 664           7 700
Первичные output tokens       2 177           2 318
Первичные всего               9 841          10 018
Дополнительные ремонты         0               2
Принятые после ремонта         6/6             4/6
Всего с ремонтами              9 841          14 611
Стоимость по тарифу           $0.0018549      $0.0027699

Первичная разница полного расхода: 1.7668% в пользу CSPL/JSON.
С ремонтами выполненные попытки CSPL/JSON потребовали на 32.6466% меньше
токенов, однако сравниваются разные доли ответов, принятых по контракту.
Это не цена гарантированного успешного завершения для обеих сторон.
Статистический вывод о превосходстве моделей/языков по шести парам не делается.

Что произошло в двух ошибочных исходных Python-ответах:
- migration_01: JSON-литерал true внутри Python-выражения;
- conflict_02: поясняющий текст перед программой и JSON-литерал false.
Один Markdown code fence одинаково допускается у обеих сторон; сам fence
не был причиной отказа. В исходных ответах fences встречаются у 5/6 обеих сторон.
Два ремонта получили исходный контекст, свой ответ и диагностику без правильных
значений. Первый сохранил true, добавил пояснение и передал версию позиционно;
второй исправил False, но оставил поясняющий текст перед программой.
Последний вызов корректен после извлечения из прозы. Второй позиционный аргумент
поддерживается реальной библиотекой, хотя не соответствует запрошенному формату.
Первичный замороженный оценщик не менялся после получения ответов.

Отдельный post-hoc разбор не изменяет основную оценку:
без исполнения кода извлекается единственный вызов compile_policy, заменяются
только AST-имена true/false/null на литералы. Исходные бизнес-пакеты Python
после этого совпадают с ожидаемыми 6/6, как у CSPL; по 378/378 скрытых бизнес-входов.
Следовательно, разница первого прохода относится к готовности ответа к загрузке,
а не к обнаруженной ошибке расчётной логики. Общий входной JSON мог способствовать
копированию JSON-синтаксиса в Python. Это диагностический разбор с известными
ответами, не новая заранее замороженная модельная когорта.

Сильный контроль той же серии принимает одинаковый JSON в обоих механизмах.
Он не требует от модели перевода true/false в Python. Поэтому наблюдаемую
разницу представлений нельзя выдавать за уникальное преимущество CSPL metadata.

Фиксация условий/оценщик: model_design/{PROTOCOL.txt,FREEZE.json,tasks.json}.
Все запросы/ответы/usage: anthropic/*.json; анализ: anthropic/ANALYSIS.json.
Диагностический разбор: model_design/diagnostics/.
Ни один сгенерированный Python не исполнялся через eval/exec.
AST извлекает данные, исполняется только наша доверенная библиотека.

подготовить проверяемую роль «можно редактировать code, нельзя менять cspl
и обработчик». Это граница найденного интерфейса, не доказательство отсутствия
backend ACL. Испытание с разными ролями не проводилось.
Область видимости, PIN и инструкции агенту не выдавались за такую авторизацию.
В аудите полномочий роли и ключи не создавались, аккаунтные данные не читались.
Подробности и матрица будущего реального теста: authorization/REPORT.txt.

Человеческое время редактирования и проверки не измерялось. Пилот с людьми
подготовлен в PLAN.txt и HUMAN_PILOT.txt; агентов за людей не выдавали.

5. Что полезно для бизнеса по этой серии

Семейство правил можно проверять и менять отдельно от общего движка.
Три уровня ограничений дают наблюдаемое влияние на скидки; дефектный общий
обработчик обнаруживается эталонными примерами, а возврат к корректной версии
восстанавливает ответы. В нашем стенде это одинаково доступно обоим маршрутам.

Если дешёвая модель получает JSON и должна вернуть данные, сохранение
JSON-представления может уменьшить число ошибок преобразования формата:
в этом пилоте две такие ошибки появились при выдаче Python-вызова.
Для потребителя одинакового JSON проверенное поведение CSPL и готового
Python-диспетчера совпало. Экономия адаптеров или операций сопровождения
именно от механизма CSPL в данном стенде не появилась.

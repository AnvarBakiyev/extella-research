# Бенчмарк повторяющихся правил: отчёт (22.10.2026)

Протокол написан до прогонов: `PROTOKOL.md`. Сырые данные: `results_sposoby_qwen9b.json`, `results_gpt.json`, `zamer_lokalno.log`; для Sonnet — прогоны 20.10 из `../zamer-navyki-vs-eksperty/`. Скрипты: `zamer_sposoby.py`, `zamer_lokalno.py`.

## Что сравнивалось

Две задачи согласования заказа: 3 правила (`zakaz3`) и 12 правил (`zakaz12`), по 50 заказов с эталоном. Четыре способа:

- **A. Навык**: правила и заказ в модель на каждый прогон, ответ JSON.
- **B. Код на лету**: на каждый прогон модель пишет функцию, она исполняется локально; код не сохраняется. Так работают Code Mode и выполнение кода через MCP без сохранения.
- **C. Сохранённая программа**: один вызов модели на создание, проверка по эталону, затем исполнения без модели.
- **D. Локальная 9B**: как C, но программу пишет Qwen3.5 9B на Mac через Ollama.

Модели: Qwen3.5 9B (Mac, Ollama, temperature 0); GPT через Codex по подписке ChatGPT (gpt-6-astra, reasoning low); Claude Sonnet 5.5 — только клетки, измеренные 20.10 (A на 3 правилах, C на обеих задачах), новых платных вызовов не было, баланс ключа исчерпан.

Выход и верность сравнимы. Секунды у GPT включают запуск Codex (около 25 с на вызов) и о скорости модели не говорят.

## Что это значит

1. **Слабая модель плохо считает и хорошо пишет код.** Qwen 9B навыком даёт 14 из 50 на 3 правилах и 4 из 50 на 12; та же модель, которую просят написать функцию, даёт 50 из 50 на обеих задачах, и на лету, и один раз. Это главный результат для «старого ноутбука»: модель на ноутбуке не должна отвечать сама, она должна один раз написать программу, а проверка по эталону отсечёт неверную.
2. **Код на лету дороже навыка на прогон и не нужен, если программа сохранена.** Выход B в 3–4 раза длиннее выхода A у обеих моделей (9B: 155 против 39 и 768 против 176; GPT: 111 против 34 и 595 против 169), на 9B и в 3 раза дольше. На сильной модели код на лету точности не добавляет (GPT: 50/50 навыком и 49/50 кодом на 12 правилах). Сохранённая программа делает то же за доли миллисекунды и ноль токенов.
3. **Безубыточность сохранённой программы по-прежнему второй прогон** у всех: создание стоит примерно один прогон навыка (1123 против 1052 у Sonnet на 3 правилах; 396 против 326 у Qwen).
4. **Выигрыш равен числу прогонов**: на 100 прогонов около 100×, на 1000 около 1000×, это арифметика, не отдельный замер.

## H200: оценка по опубликованному замеру, не наш прогон

Своего замера на карте нет (аренда отложена). По InferenceX (SemiAnalysis) Llama 3.3 70B в FP8 на одной H200 даёт порядка 1 300–3 000 выходных токенов в секунду на карту в зависимости от скорости на пользователя. Если взять 2 000 ток/с и считать, что время определяется выходом:

| Способ, задача | Выход на прогон | GPU-секунд на прогон | Прогонов в сутки на одну H200 (100 % загрузки) |
|---|---|---|---|
| A навык, 3 правила | ~55 | ~0,03 | ~3 млн |
| B код на лету, 3 правила | ~110–155 | ~0,06–0,08 | ~1–1,5 млн |
| B код на лету, 12 правил | ~600–770 | ~0,3–0,4 | ~0,2–0,3 млн |
| C программа | 0 | 0 | не нужна |

Вывод из оценки: при 10–100 тысячах прогонов в день речь идёт о долях одной карты, и разговор «100 карт против 50» не возникает. Он возникает, когда повторяемых прогонов десятки и сотни миллионов в день; тогда число карт равно прогонам в день × GPU-секунды на прогон ÷ 86 400, и сохранённая программа убирает из этого произведения весь повторяемый объём. Сколько у конкретной компании такого объёма, показывает только её журнал вызовов.

## Чего не утверждать

- Числа H200: это чужой замер на другой модели и других запросах, пригоден для порядка величины, не для коммерческого обещания. Свой замер на карте нужен до любого текста с цифрой карт.
- Входные токены GPT через Codex.
- Переносимость на другие задачи: две задачи, один день.
- Что CSPL как язык экономит токены: здесь измерена замена вызовов модели исполнением сохранённой программы; язык программ Python.

Источники по H200: InferenceX, сравнение H200 с MI355X и MI300X на Llama 3.3 70B (https://inferencex.semianalysis.com/compare/llama-3-3-70b-h200-vs-mi355x, https://inferencex.semianalysis.com/compare/llama-3-3-70b-h200-vs-mi300x).

# Бенчмарк повторяющихся правил: протокол (написан до прогонов, 22.10.2026)

## Вопрос

Сколько стоит выполнять повторяющуюся задачу с правилами тремя способами, в токенах, деньгах по тарифам на дату, секундах и, после замера на карте, в часах H200. Четвёртый способ: локальная модель 9B на обычном компьютере.

## Задачи

1. `zakaz3`: согласование заказа, 3 правила (`zamer-navyki-vs-eksperty/dataset.json`, 100 заказов с эталоном, seed 20260927).
2. `zakaz12`: согласование заказа, 12 правил (`zamer_long.py`, 100 заказов seed 20261020, эталон функцией человека).

Для бенчмарка берутся первые 50 заказов каждой задачи. Правила и входы одинаковы для всех способов.

## Способы

- **A. Навык.** Правила и заказ идут в модель на каждый прогон, модель отвечает JSON. 50 вызовов на задачу.
- **B. Код на лету.** На каждый прогон модель пишет функцию под этот заказ, функция исполняется локально, ответ проверяется по эталону. Текст кода не сохраняется между прогонами. 50 вызовов на задачу. Это то, как работают Code Mode и выполнение кода через MCP, без сохранения.
- **C. Сохранённая программа.** Один вызов модели на создание функции (из `results_claude_<модель>.json` и `results_long_<модель>_12.json`), проверка по эталону, затем 50 исполнений без модели.
- **D. Локальная 9B.** Как C, но программу пишет Qwen3.5 9B на Mac через Ollama; считаем попытки до прохождения эталона (до 3) и время; исполнения без модели.

Модель для A–C: claude-sonnet-5-5 через агента `zamer-claude` (effort low, без инструментов, системный промпт в четыре строки, ~300 токенов входят в каждый вызов). Пауза 1,5 с между вызовами.

## Что считаем

- Токены вход/выход из `usage` каждого вызова; для D — `prompt_eval_count`/`eval_count` Ollama.
- Деньги по тарифам Anthropic на 22.10.2026: Sonnet 5.5 — 2 $ / 10 $ за миллион (вход/выход); для сравнения Haiku 5.5 — 0,10 / 0,50. Для D — 0 $ за модель.
- Верных из 50 по эталону; для B — верных по результату исполнения, падения кода считаются неверными.
- Секунд на прогон (вызов + исполнение).
- Экстраполяция на 10 000 и 100 000 прогонов в день по измеренным средним; это арифметика, не замер.

## H200 (отдельный замер, после аренды)

Одна H200 (SXM, 141 ГБ) на 2–3 часа у RunPod или сопоставимого поставщика; открытая модель класса 70B в FP8 через vLLM. Прогнать запросы способа A (навык) и B (код на лету) для обеих задач батчами 1, 8, 32, 64; записать токены в секунду (вход и выход отдельно), задержку p50/p95. Из этого: H200-секунд на прогон, H200-часов на 10 000 и 100 000 прогонов в день, число карт при равномерной нагрузке и с запасом ×2 на пики. Результат относится к этой модели, этой карте и этим запросам; на другую модель не переносится.

## Ожидания до запуска

- C дешевле A начиная со второго прогона (замер 20.10).
- B дороже A на прогон (выход длиннее: код вместо JSON), верность не выше A на сильной модели.
- D: программа проходит эталон не позже третьей попытки на 3 правилах; на 12 правилах с вероятностью ~2/3 с первой (замер 20.10).
- На H200 главный расход у A и B — выходные токены; выход B в 3–5 раз длиннее A.

## Чего не утверждать

- Числа карт для конкретной корпорации: зависят от доли повторяемых задач, её даёт только журнал вызовов клиента.
- Переносимость на другие задачи: две задачи, один день, одна сильная модель.
- Экономию от CSPL как языка: здесь измеряется замена вызовов модели исполнением программы, язык программы — Python.
